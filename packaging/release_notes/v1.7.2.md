**LmCoop 1.7.2: crashes are always recorded.**

- **A crash now leaves its own trace file** (`crash_trace_<id>.txt` in the data folder), written by the crash handler
  itself, separate from the run log. It is made at the moment of the crash, so it exists even if the log could not be
  opened. The next start attaches it to the crash report and then removes it.
- **Stack overflows are reported properly.** Until now a stack overflow (`0xC00000FD`) died without leaving a trace,
  because the report needed stack that was no longer there. The faulting thread's call chain (module + offset, so the
  repeating function is visible) is written first, with a small reserve of stack kept for it, and the full report is
  made on a fresh thread. Tested with a forced overflow in the real program: the state shows a crash, the trace lists
  the repeating frame, and the report carries it.
- **The run log is no longer lost when the previous process is still closing** (after an update restart or a crash):
  the start waits up to 3 seconds for the old log to be released before replacing it.

Includes everything in 1.7.1 and earlier. No retail game data is included; supply your own USA disc dump
(GLME01 revision 0).

Based on rob646464/luigis-mansion-recompiled, with Aurora by encounter and the
SomeJakeGuy/lm-decomp reference. libdatachannel (MPL-2.0), MbedTLS and nlohmann/json are used, and the
Steamworks SDK's `steam_api64.dll` is redistributed with the program; see NOTICE.md.
